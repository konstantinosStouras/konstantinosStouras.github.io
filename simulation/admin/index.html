Admin sign-in

The platform is in LOCAL mode (no Firebase configured). Add the maintainer key to the URL (?key=…, same convention as the other lab admin panels) to open this panel. In LOCAL mode your edits apply only to this browser until you commit the downloaded config.json.

Simulations

Tick Active to show a simulation on the student page. A pinned Session ID pre-fills the student launch dialog (students can still change it); the card note shows on the student card (e.g. “Play after the lecture break”).

Simulation admin consoles

Every simulation keeps its own admin panel (and its own backend) — create sessions with the parameters of your choice there, then pin the resulting Session ID above. Panels are same-origin, so they open right here in the frame; each one signs in against its own Firebase project. Save your shared credentials below and the Sustainable Supply Chains, Search, PortfolioFit and Answer Arena consoles sign themselves in; the Ideation Challenge still asks once per browser.

Shared admin credentials (optional)

If your simulations share one admin e-mail/password, save it here and consoles opened below sign themselves in — wired into Sustainable Supply Chains, Search, PortfolioFit and Answer Arena (the Ideation Challenge would need a rebuild to join; recipe in the README). Saved per browser tab by default; nothing is ever committed or sent anywhere except to Firebase when a console signs in.

Registered students

A central roster needs the Firebase backend. In LOCAL mode each student's details stay in their own browser (and still flow into every simulation at launch) — collect participation from each simulation's own data exports instead.

Loads by itself and stays live — a student appears here the moment they register (or next open the student page, for pre-existing registrations).
